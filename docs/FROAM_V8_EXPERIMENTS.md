# Froam v8.0 — Interface Laboratory

Froam v8 turns the separately flagged v7.2 Labs into one coherent Interface
Laboratory. Every experiment reuses the stable identity, project graph,
branches, checkpoints, operations, Product Flow and shared interaction model.
No experiment replaces live-DOM editing, Rooms, Blueprint, or path-based code
generation. Froam Space is not part of this release.

## Laboratory systems

- **MUTATE:** deterministic local provider plus a replaceable provider boundary;
  Safe, Experimental and Unhinged levels; domain and node protections; preview;
  child-branch materialization; branch comparison; conflict-refusing adoption.
  The source branch is never mutated by prototype creation.
- **Interaction Library:** searchable/editable portable recipes, semantic roles,
  contextual rebinding, provenance, confidence, unsupported-signal disclosure,
  timeline trimming and deterministic preview frames.
- **Native Sampling:** records observable events, DOM mutations, geometry,
  selected computed styles, visibility, scroll and public Web Animations timing
  on Froam-controlled DOM. It reconstructs behavior, never original source.
- **External Sampling prototype:** an unpacked Manifest V3 extension runs only
  after a user clicks its action on the active tab. Froam validates explicit
  origin permission, sanitizes observations, excludes sensitive inputs, applies
  size limits and retains only origin-level provenance.
- **Physics and Gravity:** deterministic spring/throw/2D simulation, eight
  materially distinct presets and attract, repel, follow, anchor, stay-near,
  avoid and group forces. Layout-changing modes require an explicit Lab opt-in.
- **Chaos Testing:** reversible adapter-driven viewport, content, asset, RTL,
  network, API, permission and session scenarios. Findings prioritize critical
  responsive failures and persist as analyses.
- **Synthetic UX:** a deterministic local test-user provider walks Product Flow,
  records goal completion, friction and replay. The provider interface allows
  future evaluated agents; this prototype is not evidence of human behavior.
- **UI Sound:** project audio assets attach to shared interaction feedback with
  timing, volume, pitch and haptic intent. Preview requires a user gesture and
  referenced assets cannot be silently removed.
- **Trailer:** editable 10, 15 or 30 second storyboards are generated only from
  real project screens, flows and interactions. Capture/export is an adapter
  boundary, not fabricated rendering.
- **Screenshot state intelligence:** conservative appearance, disappearance,
  movement and restyle hypotheses plus multi-reference responsive inference.
  Hypotheses never become Interaction recipes automatically.
- **Reality research:** bounded probable-screen detection and quadrilateral
  rectification with deliberately low confidence and mandatory manual review.
  There is no scene understanding, camera calibration or v9 spatial workspace.

## Safety and compatibility

All v8 Laboratory flags default to off independently. The project schema stays
at v2; v8 adds recognized relation/analysis kinds and optional metadata, so old
full and packed projects continue to deserialize. Canonical events, IDs,
checkpoints and `froam.design.json` behavior are unchanged. Runtime and generated
selectors remain path-based.

MUTATE adoption compares the destination with the fork base and rejects
conflicting changes. External observations contain neither source code nor form
values. Native recording installs bounded listeners/observers and returns a
stop function. Chaos adapters restore the host after every scenario, including
failure paths.

## Maturity and limits

MUTATE, Interaction Library, Native Sampling, Physics, Gravity, Chaos, Sound,
Trailer and screenshot-state analysis are Experimental. External Sampling has
a working security-constrained prototype but remains Experimental and must be
tested only on pages the user owns or may inspect. Synthetic UX and Reality
remain Research. Physics is deterministic approximation, not a browser layout
engine. Sound export depends on a host/runtime adapter. See the privacy and
performance documents for the processing and measurement boundaries.
